# 不同课程，讲义要怎么变

本仓库的骨架是**默认值**，不是铁律。真正决定一篇讲义长什么样的，是这门课的四个属性。
判定结果落成 `<讲义库>/00-课程画像.md`（`python tools/course_profile.py` 生成），
agent 每写一个知识点都要对着它写。

## 一、四个轴，每个轴改变什么

| 轴 | 它管什么 | 改了会怎样 |
| --- | --- | --- |
| `presentation` 呈现 | 谁为准、挑哪一刻截图、图怎么用 | 判错 = 抄了老师的口误，或截了半截推导 |
| `discipline` 学科 | 红线集、字数系数、自测题型 | 判错 = 复查时查了不相关的项，真问题漏过去 |
| `style` 风格 | 每个知识点的固定小结构 | 判错 = 数学课没推导、电路课背不完 |
| `assessment` 用途 | 骨架落点、自测形式 | 判错 = 讲了半天用不上（要考试却给了项目步骤） |

## 二、五种风格，五种小结构

`course_profile.py` 按 `style × assessment` 取出骨架，写讲义时**按这个顺序写，别自创**。

| style | exam | project / understanding |
| --- | --- | --- |
| `derivation` 推导密集 | 起点 → 推导（一步一行）→ 结论（可直接抄进答题纸）→ 常见考法 | 要解决的问题 → 每步动机 → 结论与物理含义 → 换条件会怎样 |
| `judgement` 判据密集 | 判据 → 判据来源（一句）→ 典型取值表 → 反例 | 判据 → 怎么测 → 读数判读 → 读错先查哪里 |
| `concept` 概念记忆 | 定义 → 与最易混项的区别（表）→ 反例 → 记忆钩子 | 它解决什么问题 → 定义 → 与相邻概念关系 → 能讲给人听的例子 |
| `practice` 实操 | — | 目标 → 步骤 → 判据 → 失败排查顺序（按概率排） |
| `narrative` 论证 | — | 论点 → 证据链 → 反方与回应 → 适用边界 |

### 例子：同一段内容，两种课写法完全不同

> **场景**：一集讲「三极管放大电路的静态工作点」。

- 如果 `style=judgement`（模电类）：核心是**判据与取值**——
  `U_CEQ` 落在什么区间算放大区、`R_B` 改多少会让它进饱和，配一张典型取值表和一个"刚刚好在边缘"的例子。
- 如果 `style=derivation`（电路分析类）：核心是**推导链**——
  从 `I_BQ=(V_CC-U_BEQ)/R_B` 一路推到 `U_CEQ=V_CC-I_CQ·R_C`，每步为什么能这么代，中途哪个假设被用了。

同一份转写、同一批截图，两种写法的知识点划分、图的选择、甚至字数预算都不一样。
所以**画像必须在动手前定**，写完再"调风格"等于重写。

## 三、呈现方式的例外清单

| 情况 | 处理 |
| --- | --- |
| 投影上只有题目，推导全是现场手写 | 记 `mixed`；以手写为准，投影只当题面 |
| 板书与口播冲突 | 以板书为准，并在复查表记一条「原片口播与板书不一致」 |
| 老师中途跳过若干页/若干小节 | `ppt` 型必须显式标「老师没讲」，不许假装讲过了 |
| 只有讲义 PDF、没有视频 | 记 `handout`，正文顶部加降级声明，不许写"看过原片" |
| 录屏分辨率低 | 关键算式必须裁切放大再核；放大后仍不清就标 `[模糊]`，不许猜 |

## 四、什么时候该换画像

不是每集都重做。只有这三种情况改：

1. 第一次做这门课（必做）；
2. 中途发现某轴判错（例如实际是 `mixed` 判成了 `blackboard`）——改文件并记一条理由；
3. 用户明确改变用途（"不考试了，要做项目"）。

**禁止**：为了省事临时改参数而不改画像文件——那样下一个人（或下一集）会照着错的画像写。

## 五、agent 的具体义务

1. 写第一个知识点前，先 `read` 一遍 `00-课程画像.md`；
2. 每写完一个知识点，对照骨架四项看齐不齐（缺项就补，不许"意思到了就行"）；
3. 交稿前过一次红线清单（学科红线机器查不出）；
4. 画像与通用规范冲突时：**第一原则（读者没有纠错能力）> 课程画像 > 通用规范**。

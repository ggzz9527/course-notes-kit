# 05 · 把它做成插件：三个先决问题的答案

> 这份文档记录的是**判据**，不是结论的复述。任何一条判据若在别的机器上不成立，就说明结论该翻案。

## 结论（先给答案）

| 问题 | 答案 | 一句话依据 |
| --- | --- | --- |
| Q1「封装成插件」是哪种 | **(a) 分发封装**：bundle 只把 skill 注册进技能目录，不注册工具、不挂 hook | 流程里没有任何 harness 事件参与；也没有哪个步骤的非参数化错误能被 schema 防住 |
| Q2 插件与 git 仓库的关系 | **薄壳**：kit 仍是唯一真源，插件只提供「发现」，不搬动脚本 | 只有这样才能保住「git clone 完能跑」这条最强验收 |
| Q3 preset 要不要改 | **不改**。要改的是 docs（3 处） | 技能注册落在全局层，preset 的作用域链自然能看见它 |

---

## Q1：三选一，为什么是 (a)

三个候选的差别不是「贵不贵」，而是**能不能被证伪**：

| 候选 | 交付物 | 装没装上怎么看出 | 成本 |
| --- | --- | --- | --- |
| (a) 分发封装 | bundle 里的 `skills/` 目录 + 一次 provider 注册 | skill 出现在目录里，且资源基址指向包内 | 0（无 schema、无 hook） |
| (b) hook 型 | 挂某个事件的回调 | 事件触发时才看得出，平时不可见 | 0 schema，但要挑对事件 |
| (c) tool 型 | 注册工具 | 工具数 + N，每轮多 N 份 schema | 几百 token／轮 |

### 排除 (b)：流程里没有可挂的事件，唯一能挂的会开错后门

- 这条工具链的全部动作都是**模型按 SKILL.md 主动跑 CLI**，没有任何一步发生在「harness 事件」上：没有审批语义要改、没有生命周期要接管。
- 唯一现成能挂的是审批事件。它的 payload 只有 `{ agent, toolName, reason, callId }`，**没有命令行参数**（这一点由已装插件 `dsh-approval-mailer` 的实现注释与本机实测共同确认）。
- 所以按 reason 放行等于：只要理由里出现某个词，`course_prep.py audio` 这种「联网下载 + 调 ffmpeg + 写盘」的命令就自动通过。**这正是本流程最不该自动化的那一步**——它比不装插件更危险。
- 结论：**不给审批开白名单**。这也是 (b) 被排除的硬理由，不是"没必要"。

### 排除 (c)：4 个候选逐个打分，没有一个达线

判据（四条全过才值得做工具）：

1. **重复性**：每个会话/每集要做。
2. **参数结构化**：参数不是自由文本。
3. **CLI 易错**：命令行写法容易错，而 schema 能防住这类错。
4. **不变量**：工具能守住一个 CLI 守不住的不变量。

| 候选 | 重复 | 结构化 | CLI 易错 | 新不变量 | 结论 |
| --- | --- | --- | --- | --- | --- |
| `course_run.py shots`（`t:crop:x1,y1,x2,y2:scale:name` 那个语法） | ✅ 每集 6–8 次 | ✅ 可拆成 t / box / scale / name | ✅ 冒号语法确实容易错位 | ❌ 不变量（无二次裁切）已由 `course_gate.py rects` 守 | 3/4 |
| `note_check.py <集目录>` | ✅ | ⚠ 只有一个路径 | ❌ | ❌ | 1/4 |
| `course_gate.py report`（`--read-images N --strict`） | ✅ | ⚠ 路径 + 一个整数 + 一个开关 | ❌ | ❌ 闸门本身就是 CLI | 2/4 |
| `course_scan.py merge` | ✅ | ⚠ 目录 + 一个 JSON 文件 | ❌ | ❌ | 1/4 |

`shots` 差的那一条是决定性的：它的不变量已经在下游用**时间邻近**（`--tight 10`，用真集校准过 10 秒抓 2 对真重裁、0 误报）守住了。再加一个工具，等于同一个不变量有了两个入口——而这份仓库里最贵的一类事故就是「两份要同步的东西悄悄漂了」（`derive_publish` 的逐字 4 / 派生 8 就是为此存在）。**所以不是"省 token 所以不做"，而是"做了会多一个漂移面"。**

### 排除 (c) 的第二条理由（可数）

preset 的交付判据之一是「数 `- id:` 行」。加一个工具，这个数就从 21 变 22，而 `docs/02` 第 3 条判据（零运行逻辑、白名单固定）当场失效，必须同步改。**一个只为省几次打字而做的工具，会连带把三条验收判据改掉**——代价与收益不成比例。

## Q2：薄壳，不是取代

### 判据

| 方案 | 「git clone 完能跑」 | 可移植性 | 后果 |
| --- | --- | --- | --- |
| 插件**包着** kit（薄壳） | ✅ 保住 | ✅ 插件只管发现 | 需要一条同步闸门 |
| 插件**取代** kit 的分发 | ❌ 失效 | ⚠ 插件成了唯一入口 | `docs/02` 整节重写，最强验收作废 |

选前者。**「git clone 完能跑」是这套包里唯一一条不依赖 DSH 的验收**，一旦插件成了分发入口，它就只能在装好插件的机器上验证——那等于用被测对象去证明被测对象。

### 由此产生的约束（不是可选项）

1. 插件里的 `skills/course-selflearn/` 是 kit 的**逐字副本**，不是改写版。拷文件一律二进制（`shutil.copyfile`）：文本模式在 Windows 上会把 LF 翻成 CRLF，结果是 `git status` 说改了、`git diff` 是空。
2. 副本与真源之间必须有**双向**闸门：分发者工作区里有一次性核对（**本包不带**，所以这里不给路径——给了就是「照做文件不存在」）。它同时查「插件里少了/多了/字节不同」和「bundle 自洽」：`type: module`、`exports` 暴露 `./package.json`、`dsh.bundle.patch` 指向的文件存在、patch 用 `- insert:` 包住、patch 的 `name:` 是官方 provider、`includeDefaultRoots: false`、`customSkillDirs` 里那条 `!!js` 的**语法**（用 `node -e 'new Function(...)'` 只编译不执行）。
3. **不做成「插件直接读 kit 目录」**：那会把本机绝对路径焊进配置，正好违反 SKILL.md §七「不绑定任何机器路径」。
4. **插件里没有 `index.js`，纯配置。** 这不是风格选择，是实测约束：插件是以 `link:` 装进 profile 的，Node 对裸模块名按**真实路径**解析，而链接包的真实路径在工作区——那里没有 `@deepseek-ai/*`。所以 `import { FileSystemSkillProvider } from '@deepseek-ai/dsh-skill-filesystem'` 会 `ERR_MODULE_NOT_FOUND` → `1 entry did not activate`（第一版就是这么失败的）。把导入交给 loader（patch 的 `name:` 由 loader 用 profile 的 baseUrl 解析）才通。

### 回滚语义（必须成立）

删掉插件 → 退回原行为：`<工作区>/.dsh/skills/course-selflearn/` 这份手工副本照旧被默认根目录扫到。**两条路互不依赖**，这也是「删掉退回原行为」可以真做实验的前提。

## Q3：preset 不改；改 docs 三处

### 判据（源码级）

`@deepseek-ai/dsh-skill` 的采集顺序是「全局层 + 视图作用域链」，后写入的同名项覆盖先写入的：

```
lib/index.js:299   const layers = [this.layers.global, ...this.layers.chainLayers(options.scope)];
lib/index.js:305   for (const entry of collected.entries) merged.set(entry.candidate.name, entry);   // 后者覆盖
```

插件这条 row 落在 **profile 根**（全局层），所以任何 preset 的视图都能看见它。已装的两个同类插件把这件事写在了自己的实现注释里（`dsh-logicprobe` / `dsh-embedded-workbench`：注册落在全局层，任何 preset 都看得见），并且它们的 skill 确实出现在本会话的目录里——**源码 + 现成实现 + 可观察结果三者互证**。

### 所以这些数一个都不变

| 判据 | 现值 | 怎么数 |
| --- | --- | --- |
| preset 的 `- id:` 行数 | **21** | `grep -c '^\s*- id:' preset/agent.cordis.yml` |
| 工具数 | 约 20（不是 175） | 新会话问「列一下你有哪些工具」 |
| 工具 schema 体量 | ≈ 14,534 字符 ≈ 3,633 token | 见 `preset/agent.cordis.yml` 头部实测记录 |

**注意**：`docs/02` 原来只有「数 `- id:` 行」这个方法，没有写期望值。这次把 **21** 写进去——判据没有期望值，下一个人数出 22 也不知道该不该报警。

### docs 要改的 3 处

1. `README.md`：目录树加插件位置；「安装」一节加「想让 skill 出现在每个会话里」这一步。
2. `docs/02-安装-preset.md` §五：原来写「本包把『插件』定义为 (b) agent preset，不是 cordis 插件」——这句话现在不成立了。必须改成：**preset 管 token 预算，bundle 管 skill 发现，两件事别混**，并保留原判据（零运行逻辑、可回滚）。
3. `docs/02`：新增一节装 skill bundle（先备份、再装、再验、最后回滚），把 21 这个数写进判据表。

插件化之后额外两条：

- **A 冷启动**：在非 `%TEMP%` 的路径 `git clone` 一份（关掉 hardlink 复用），三个脚本在干净环境里全绿。
  （`%TEMP%` 下 `makedirs` 会撞 `PermissionError [WinError 5]`——删除挂起 / 杀软句柄。这是环境坑，不是脚本问题。）
- **B 按 docs 从零装一遍**：`docs/02` 每条判据都要能重新数出对得上的结果。
  **插件装了 ≠ 流程能跑**：所以 B 里既验 skill 出现在目录，也验 `selfcheck` 仍是 7/1/0。

## 反转验证（只跑一次绿不算证明）

| 状态 | 观测量 | 实测 |
| --- | --- | --- |
| 基线：不装插件，手工副本在 | 技能目录里有 `course-selflearn` | ✅（会话开始就有，当时插件还不存在） |
| 装插件 | 技能目录里多出探针 skill，且它的**资源基址**是本包内的 `skills/<名字>` | ✅（`.../plugins/dsh-course-selflearn/skills/zz-probe-skill`） |
| 卸插件（`remove_bundle`） | 探针从技能目录消失，`course-selflearn` 仍在 | ✅（同一会话内，无需重启） |
| 再装回去（`install_bundle`） | 探针回到技能目录 | ✅ |
| 删掉探针目录 | 探针消失（provider 的 watcher 生效） | ✅ |
| 把手工副本的正文换成占位文本 | 技能目录里显示的是**占位文本**（说明近的层赢） | ✅ |
| 再删掉整个手工副本 | 技能目录里变回**发布版正文的描述**——只有插件那一份有它 | ✅（这一条才真正证明「正文也是插件供的」） |
| 复原手工副本 | 回到本机版（`sha256` 与备份一致） | ✅ |

为什么不直接拿 `course-selflearn` 本身做这条实验：它的正文有几十 KB，每加载一次都会被后续每一步重放。**探针与它走同一个 provider、同一个根**，所以「供 skill 的机制」用探针验，「内容逐字」用同步闸门验——两件事分开测，代价从几十 KB 降到几十字节。

**只看「skill 能用」不算**：手工副本一直在时，插件没生效也照样能用（实测：卸掉插件后 `course-selflearn` 仍然在目录里，因为它在手工副本里）。唯一能区分「谁供的」的观测量是**资源基址**。

## 没有做的一件（明确记录）

`scrub_kit.py` 的「真实 BV 号」规则只从各课库的 `_course.json` 现读，而现库里只有 1 个真实 BV 号进了 deny-set（实测输出：`真实 BV 号 1 个`）。对照实验的结果是：植入 deny-set 内的 BV → rc=1（规则会响）；植入库里真实存在但未入 deny-set 的 BV → rc=0（放过去了）。

⇒ **「scrub 过了」只能推出「deny-set 里的东西没漏」，不能推出「没有泄漏」。** 加宽采集源（全库扫描，实测 377 文件 / 0.09 s）是另一件事，不在本次改动范围内。

# 工具与踩坑

> 全部用标准库为主；子进程一律用**重定向到文件**的方式收输出，不用 `capture_output`
> （某些沙箱环境禁命名管道，会 `PermissionError(WinError 5)`）。

## 脚本一览

### `course_run.py` —— 一次拉课的机械段

| 子命令 | 干什么 | 关键参数 |
| --- | --- | --- |
| `fetch <BV> <ep>` | meta→音频→转写→视频→抽帧→帧核验，一条命令 | `--no-video` 只要音频；`--min-frames` 断点阈值；`--force` 全重做 |
| `shots <集目录> <specs...>` | 帧 → 裁切/放大 → `assets/epNN-tNNNN-名字.png` | `t[:crop:x1,y1,x2,y2[:scale[:名字]]]` |
| `check <集目录>` | 转调 `note_check.py` | `--frames-csv`、`--tol` |
| `rank <媒体目录>` | 给出每帧「投影/板书/空板/人物」分类表 | `--every`、`--top` |
| `digest <媒体目录>` | 转调 `course_digest.py` | `--llm` |

**输出一律以 `MANIFEST` 段结尾**（每个文件大小、帧数、时长、转写段数、失败步骤），
一次读完不用再 `ls`。

### `course_prep.py` —— 素材下载

`meta / audio / video / frames / verify` 五个子命令。音频优先：转写只要 20~25 MB，
先下音频就能出稿，不必等整集视频。

### `course_digest.py` —— 转写压缩

```bash
python tools/course_digest.py <媒体目录>          # 机械稿 digest.md（只压到 87%，够查证不够读）
python tools/course_digest.py <媒体目录> --llm    # + 知识点候选卡（走你自己的模型）
```

**已知缺陷（必须知道）**：

1. 摘要**继承转写错字且不加标注**（「恒流」→「横流」、「绝缘栅」→「绝缘山形」）；
2. 分多段调用会**整段丢内容**（实测漏过 8 分钟）。

⇒ 只当「目录 + 时间戳索引」，写讲义必须回 `ts.txt` 核。

### `note_check.py` —— 机械自检（9 类）

字数带宽 / 单点预算 / 图后解读 / 禁用词 / 图片坏引用+孤图 / 图号连续性 /
每张图有无讲解 / frontmatter 必填 / status↔复查表一致。

退出码 0 合格 1 不合格；`--json` 给机器读；`--frames-csv` 追加帧残差核验。

### `course_scan.py` —— 批量筛帧

`list` 出待判清单 + 提示词（`--json` 给 workflow 直接吃），`merge` 并表成段落表。
脚本**自己不调 API**（很多沙箱直连图像 API 会超时），读图交给会话里的 `workflow`。

## 踩坑表

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| `-ss` 放在 `-i` 之后 | 每帧从头解码，292 帧要 40 分钟+ | `-ss` 必须前置 |
| CDN 节点超时 | 整段 TLS 超时 | playurl host 换可达 mirror（签名随路径，换 host 仍有效） |
| ffmpeg 打不开某 CDN | 下载失败 | 用 urllib 分块下载，再本地 ffmpeg 合并 |
| 沙箱禁命名管道 | `subprocess.run(capture_output=True)` → `PermissionError` | 重定向到文件再读回 |
| `av` 版本 | faster-whisper `TypeError: metadata_errors` | 必须 `av==13.1.0`（`av>=15` 删了这个参数） |
| CPU 转写慢 | 默认 beam=5 只有 0.4 倍速 | `WHISPER_BEAM=1`、`WHISPER_THREADS=核数` → 7 倍上下 |
| 想用 GPU / 术语不准 | 默认走 CPU、无提示词 | `WHISPER_DEVICE=cuda`、`WHISPER_PROMPT="你的术语词表"` |
| 后台跑 pip | 假死（输出管道没人读） | 重定向到文件 |
| 帧文件命名 | 猜成 `f0003` 实际是 `f_0030` | 先 `ls` 看命名 |
| 时长列「—」 | `_course.json` 缺 `duration` | 补进 `episodes[].duration` |
| 模型传字符串 | HTTP 400 JSON parse error | 必须传 `messages` 数组 |
| 换视频后重跑 `frames` | 报「帧就绪 N 张」、exit 0，帧却是上一支视频的 | 看 `frames/.source.json`；对不上会整目录作废重抽 |
| 用体积判「出了帧」 | 低熵画面（纯红 320×240 = 799 B、720P 纯白 4.3 KB）被判「没抽出来」，exit 1 | 查 PNG 头 8 字节签名，别拿体积猜 |
| 对账脚本不带参数 | 从工作区根跑 = 审整棵树：11 个幽灵脚本 / 87 个假选项 / 裸 traceback | 目标目录锚 `__file__`，指错就 exit 2 |
| `COURSE_FFMPEG` 全大写 | `FFMPEG.EXE` 推不出 ffprobe，又拿 ffmpeg 跑 ffprobe 参数 | `_sibling` 大小写不敏感 |

## 产物身份（2026-11-25）

这条是上面「换视频后重跑 frames」的根因，单列出来，因为它能推广到整条链。

**六层根因修完之后，同一个病从别的入口又冒出来了。** 六层守的全是「本次调用的返回值」，
没有一层守「落盘的东西属于这次输入吗」。用状态机验（`logicprobe`，不变量
`never-states: DONE_STALE`）拿到 3 步反例：

```
extract（抽 A 的帧）→ swap_to_B（目录换成 B）→ report_ok → 报就绪，而帧还是 A 的
```

第一版修法「抽帧时把源视频写进身份证」**被同一条反例证伪**——视频是抽完之后才换的。
真正要守的是「报成功那一刻」：**通往成功的每条路都必须带校验，无条件的「报成功」要删掉**。

落地成四条：

1. `frames/.source.json` 记源视频名/大小/mtime；不匹配（含「有 png 没身份证」的老目录）→ 整目录作废重抽；
2. 报「本次新抽 N 张」，不报目录总数；`have < expect` 直接 exit 1；
3. `course_verify.frames_identity()` 是共享判据，`note_check` 接上：`stale` → 错、`unknown` → 警；
   残差只说明「时间对得上」，不说明「帧是这一集的」；
4. `gen_lib.py` 写 `.genlib-manifest.json`（`generated_at` / `kit_rev` / `_course.json` 指纹 / 集数）——
   索引是一次运行的快照，没有身份就判断不了新鲜度。

**判据必须能失败**：`scripts/regress_frames.py` 六个场景，每个 FAIL 都对应一次真实发生过的谎报。
改抽帧相关代码后必须跑；它单独成脚本、不并进 `selfcheck`，因为 selfcheck 的契约是「不改任何文件」。

### 下载：同一条不变量的另一半（2026-11-26）

抽帧那条链盖住之后，整条链的薄弱点移到下载——比抽帧更隐蔽：**帧错了讲义看得见，
文件残了要到转写出乱码才发现**。`scripts/regress_download.py` 用同样八个场景守
**不存在「报成功但落盘文件是残的」的可达状态**。

反例是上一轮被打回的那一版：只在**下载时**守分片长度。但 `ffmpeg -c copy` 对截断流
**可能返回 0**，于是三步就报了成功：

```
INIT →(start)→ DOWNLOAD →(dl_ok)→ REMUX →(ff_corrupt)→ DONE     成品是残的
```

`logicprobe` 跑出来 `no-false-done` 违约、最短反例 3 步。所以判据必须落在**成品**上，
下载时守得再好也不算：加一个 `VERIFY` 态，报成功前 `ffprobe -show_entries format=duration`
读一次，与 `meta.json` 的 `duration` 比（容差 1 s）。

三条同类的判据平移（都是「别拿近似量猜内容」）：

1. **体积猜不出来**：`getsize > 1000` 判 PNG、`getsize > 1MB` 判音频，都在某个角落错过。
   低码率集和残件都能「够大」。
2. **时长也只是一半**：`ffprobe` 的时长来自容器头，半个文件只要 moov 还在照样报全长。
   所以另记一份身份 `<文件>.id.json`（字节数 + 时长），**字节数只与上次核过的记录比**，
   不与「大概应该多大」比。
3. **残渣要按族清**：分片是 `<mid>.part.0..N`，workers 数变过时旧的 `.4..7` 会被当成本次
   结果拼进去——那是「继承」，不是重下。
4. **「产物」要按模式定，不能按文件名定**：`--keep` 的产物是片段，不是整集。
   老代码 `if os.path.isfile(dest) and getsize > 10MB: return 0`——整集在、片段一个都没有，
   照样报成功。同一个谎报换了入口：**判「完成」必须按这次请求要的产物判**。

**变异测试**：五个变异（去掉原始直链回退、成品核验放行、不核字节、不清残渣、
`--keep` 退回「有文件就当完成」）都必须让回归变红，
而且红的必须是**声称守住它的那条场景**。第一版判据写出来时 A/F 是靠「ffmpeg 恰好合不了截断流」
和「时长读不出」变红的——看着对，其实没测到新增的守卫；改成在判据里钉住
`字节数不符` 这条日志、并把残渣名换成真实那一族之后才真正测到。

### 让判据自证「跑的是哪棵树」（2026-11-26）

判据最危险的失效方向不是误报 FAIL，是在**错的输入上误报 PASS**。回归脚本也一样：
在别人 fork、旧版本目录、或自己的开发副本上跑一遍，然后签字说「发版前验过了」。

三个对账脚本早就是这么做的（锚 `__file__` + 校验「这确实是发布包」，指错 exit 2）。
两个回归脚本这一步补齐：

- `--json`：stdout 一个 JSON（`ok/script/root/rev/total/failed/results`），
  进度行走 stderr，所以 `--json 2>/dev/null` 是纯 JSON；
- `root` + `rev` 写进结果——读的人不用再问「你跑的是哪棵树」；
- 崩了也给结论（`{"ok": false, "error": "..."}`），不让调用方去猜 traceback。

`rev` 是**直接读 `.git/HEAD`** 拿的，不调 `git`：沙箱禁命名管道，`subprocess` 抓输出会
PermissionError；zip 分发的包没有 `.git`，就老实返回 `unknown`——自证是描述，不是闸门。

输出契约放在 `scripts/_report.py`，两个脚本共用一份。

**为什么不跟 stub 一样「先不抽」**：stub 依赖**被测代码**，抽早了只是多一层间接；
输出契约依赖**调用方**，两份就会分叉——模型换个脚本解析就遇到两套键名。
判据：新增的东西有没有**第二个使用者**，有就抽，没有就等。

### 判据自己会随 shell 编码漂：`regress_frames` 报 3 通过 / 3 失败

`course_prep.py` 的 stdout 被重定向到文件时，Windows 上 python 按本地代码页（中文机器 cp936）写，
而 `regress_frames.run_frames()` 按 utf-8 读回来——D/E/F 三个靠字符串匹配的判据于是全部落空。
同一个脚本，在 UTF-8 控制台里 6/0，从别的 shell 跑就 3/3。

修法是给子进程固定 `PYTHONIOENCODING=utf-8`（父进程读法不变，人手看控制台也不受影响）。
教训：**判据不能依赖调用者的代码页**；一个「有时候红」的回归比没有回归更坏，
它会训练人忽略红。

同一个道理在闸门那边：**最危险的失效方向不是误报 FAIL，是在错的输入上误报 PASS**——
所以三个对账脚本现在既锚 `__file__`，又校验「这确实是发布包」，指错直接 exit 2。

## token 账（为什么值得这么折腾）

一集课的固定开销曾经长这样：

| 项 | 数值 |
| --- | --- |
| 175 个工具 schema | ≈ 70,700 token（占首步 95%） |
| 其中桌面操控 63 个 | ≈ 50,493 token，笔记流程一次不用 |
| 首步基线合计 | **74,053** |

**钱不是花在"读笔记"上，是花在"每轮重发用不到的工具说明书"上。**
所以：能外包给子智能体的读原文，一律外包；能落盘的中间产物，一律落盘。

# 复查清单

> 复查是独立工序，不是"再瞄一眼"。目的：在读者看到之前，把错找出来。
> 触发：初稿写完，**另起一遍**，换视角——不是"我刚写了什么"，而是"读者拿这篇能不能学会，会不会被带错"。

## 一、基本纪律

1. **只列问题，不写表扬**。输出是一张问题表，不是评语；
2. **每个"通过"必须附证据位置**：`srt 03:20` / `截图 ep34-2.jpg` / `手册 p.47` / `转写第 128 行`；
3. 写不出证据的结论，一律标 `未核对`，不许静默通过；
4. 复查者不去修文，只记录问题与处理建议；改由写稿环节完成，改完再复检一次。

## 二、三层检查

### L1 事实层（逐条核）

按 `discipline` 取对应列，不要混用：

| 查项（通用） | 依据 |
| --- | --- |
| 老师原话是否被转述失真 | 字幕原文 + 时间戳 |
| 每个数字、单位 | 原文/手册，重算一遍 |
| 推测是否标了 `未核对` | 全文扫描 |

| 查项（`ee` / 嵌入式） | 查项（`math`） |
| --- | --- |
| 引脚号 | 定理的**条件**（可微几阶？在哪一点？区间还是点） |
| 电压、极性、上下拉 | 符号与幂次（$n$ 还是 $n+1$、$\xi$ 的位置） |
| 时序顺序、边沿 | 每一个"⇒"是否真成立（隐含前提有没有漏） |
| 寄存器位与含义 | 数值/量纲/百分比，重算一遍 |
| 器件参数 | 反例是否真的反（能不能构造出来） |

### L1-A 例题数值必须独立复算（2026-11-23 ep14 定）

**凡是讲义里带数字的例题，复查时用脚本重算一遍，结果写进复查表。**
不许"对着原文核一遍"就算通过——原文自己会算错。

触发案例：ep14 段 301 老师说"三分之二的 20 毫伏等于 6.67 毫伏"，
`2/3 × 20 = 13.3`，6.67 是 `1/3 × 20`（`RS` 上的分压）。连带下一句 `0.667 V` 应为 `1.33 V`。
**这一处只有复算能发现**，对照原文只会记成"一致"。

做法：

```bash
tools/venv/Scripts/python.exe -c "<把例题参数写进去，print 每一步中间值>"
```

复查表里单列一行：`原片值 / 复算值 / 差 / 处理（正文用哪个、为什么）`。
定性结论不受影响时也要写一句"结论不变，只是数值改正"，别让读者以为整段都作废。

### L1-B 视觉子代理的卡只能当线索

若这一集用了 ②-B 的批量筛选（任何视觉子代理都一样），复查时：

- 子代理给的 `kind`/`occluded`/`bbox` 可用，**`text` 一律不许进正文**；
- 抽查 5 张：主模型重读，比对子卡的 `kind` 是否一致；不一致就以主模型为准并记一条；
- 子代理返回 `null` 的帧**必须主模型亲自看**，不许当"这帧没内容"跳过（ep14 的 7 个 null 里 4 个是关键公式页）。


### L2 逻辑层

- **删句测试**：任意删掉一句，后面还读得懂吗？读不懂＝有跳步；
- 因果是否成立（"因为 A 所以 B"里，A 真是 B 的原因吗）；
- 比喻的失效边界是否与原理矛盾；
- 前后是否自相矛盾（前面说推挽，后面说开漏）。

### L3 阅读层

- 五问自足性：解决什么问题／机制／步骤及每步为什么／一个错误及现象／2 道题；
- 禁用词：显然、很简单、众所周知、大家应该都知道；
- 每张图有引导句、标号、逐点解读、对照表，且被正文引用；
- 字数：单篇 ≤ **知识点数 × 400 字**（硬上限 6000），且单个知识点 ≤ 400 字；只数正文中文，不含 frontmatter/代码块/表格/图片行。复查时**必须写出实际字数与预算**（例：`3413 / 4800 字，12 个知识点`）；
- 推测都已标 `未核对`；
- **拆篇合规**：知识点 ≥ 15 却只出一篇 → 判不通过（应在知识点表阶段就拆「上/下」）。

## 三、红线（按 `discipline` 取集，100% 查，错一个整篇不通过）

**`ee` / 嵌入式 6 类**：1 引脚号｜2 电压｜3 极性（正负/上下拉/边沿）｜4 时序顺序｜5 寄存器位｜6 公式与换算。
理由：这 6 类错误对零基础是致命的——他不会怀疑，会直接照做，然后烧板子或调不通。

**`math` 6 类**：1 定理**条件**（几阶可导、在哪一点、点还是区间）｜2 符号与幂次（$n$/$n+1$、$\xi$ 与 $\theta$）｜3 量纲与数值（重算到小数位）｜4 隐含前提（"$f''$ 在邻域存在"这类没写明的前提）｜5 公式与换算（$k!$、$(-1)^m$、符号方向）｜6 反例有效性（反例必须真能构造，不能嘴上说"可以构造"）。
理由：数学讲义错了读者照样能背下来，还会拿去考试——条件是唯一能让他判对错的东西。

**`physics` / `cs` / `humanities`**：暂沿用通用四项（事实/公式与量纲/逻辑/推测标注），等有人实测后再补集；没实测过不许凭空写红线。

### 呈现方式带来的额外必查一项

- `ppt` 型：老师跳过的证明/推导，讲义**必须显式标"老师没讲"**，并与字幕里"这个证明我们不证了""这个我们不证了""大家自己看"这类话逐句对上；
- `blackboard` 型：板书与口播冲突处，复查表必须列出"以谁为准 + 证据位置"。

## 四、主动找反证（防"看起来都对"）

挑 3 个最可能错的点（数字、方向、极性、时序），逐个主动找反证：
- 有没有第二种解释？
- 换一个数据手册版本还成立吗？
- 如果读者照做，第一步会看到什么？和正文写的一致吗？

找不到反证才算过。**不要用"我记得是这样"当反证**。

## 五、原理图二次核验

初稿阶段已按"型号/引脚/参数"核过一次；复查时**脱离初稿结论独立再核一次**，不许引用初稿的核验记录。
两次证据链必须独立（一次靠手册，一次靠原片截图/实测，或反过来）。

## 六、复查表模板

存 `90-复查/<epNN>-review.md`：

```markdown
# ep31 输入捕获 · 复查表
复查日期：2026-11-18
结论：通过 / 不通过（红线错误 N 处）

| # | 层 | 类型 | 位置 | 问题 | 依据 | 处理 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | L1 | 事实 | 知识点 K2 第 3 段 | CCR 写成"当前计数值" | srt 05:12 原话为"边沿时刻的 CNT" | 改 |
| 2 | L1 | 红线-引脚 | 图 2 对照表 | PA0 写成 PA1 | 手册 p.47 | 改 |
| 3 | L2 | 逻辑 | 第 4 节 | 跳步：没说为什么要先清零 | 删句测试 | 补 |
| 4 | L3 | 阅读 | 图 3 | 无引导句 | 清单 | 补 |

未核对项：
- 图 2 的去耦电容数量（手册版本 p.47 与 p.52 不一致）
```

## 七、状态机

```
draft ──复查通过──> reviewed
  ↑                    │
  └──不通过/发现问题───┘
```

- frontmatter `status` 只有 `draft` / `reviewed` 两值；
- `reviewed` 必须同时存在复查表且结论为通过；
- 台账（`99-台账.md`）里的完成度只统计 `reviewed`，`draft` 不算完成；
- 复查后再改正文，`status` 必须退回 `draft` 并重新复查。

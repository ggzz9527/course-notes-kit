# 课程自学讲义（零基础版）

## 第一原则：读者没有纠错能力

写这份讲义的人（你）和读它的人（零基础）之间，信息差是单向的：**读者无法发现你写错、图错、比喻错**。所以：

1. 任何一张非原片截图，默认当它是错的，核验通过才升级为"可用"；
2. 任何一句"我觉得是这样的"，都必须标 `未核对`，不许混进正文冒充事实；
3. 每篇交付前必须过 `references/复查清单.md`，红线（按学科取集）错一个就整篇不通过。

这条原则优先于本文其余所有规则。省事但会误导读者的做法，一律不做。

## 一、适用与不适用

| 适用 | 不适用 |
| --- | --- |
| 没上过课，只有课程本体（视频/合集/讲义/PPT/目录） | 上过课、只想刷题复习 → 直接给题和错点 |
| 要求"整理知识点""讲得零基础能懂" | 只要摘要/目录/课程大纲 |
| 要给别人的讲义（会脱离你所在的知识库） | 需要盖章认证的正式教材 |

产物落在独立库 `course-notes/`（见 `references/库与台账.md`），**不写进用户的知识库**，除非用户明确要求。

## 二、输入与能力阶梯

先探测本机有什么，再决定能做到什么。**能力不足时降级，绝不假装**。

| 级 | 具备 | 能做什么 | 缺什么就标 |
| --- | --- | --- | --- |
| T0 | 只有对话 | 读用户上传的视频/截图/讲义 | 无时间戳、无逐字原话 |
| T1 | 有字幕文件（srt/vtt） | 跳过转写，直接做知识点表 | 无截图 |
| T2 | + yt-dlp / ffmpeg | 下载、抽帧、按秒截图、缩略图墙 | 无逐字原话 |
| T3 | + whisper（faster-whisper 等） | 转写、按时间戳问课 | —— |
| T4 | + 联网检索 | 检索并核验网上原理图 | —— |

探测方式：`python -m yt_dlp --version`（**不要用 .exe**，PyInstaller 单文件在受限环境里解包会失败）/ `ffmpeg -version` / `python -c "import faster_whisper"` / 是否有 web_search 类工具。探测结果写进讲义 frontmatter 的 `evidence` 与 `figures`。

**实测坑（2026-11-19，Windows + 沙箱）**：
- `yt-dlp.exe` 报 "Failed to create parent directory structure" → 改用 `python -m yt_dlp`（`pip` 装不上时可直接从 PyPI 下 wheel 解压到 site-packages）；
- B 站合集常是**分 P**，不是独立 BV，用 `-J` 列全部条目再按 `pN` 取；
- 视频没有 CC 字幕时，字幕是**烧进画面**的，只能靠转写；
- 转写要选**能 import faster_whisper** 的那个 python（本机是 DSH 自带 python，不是 venv）；
- 挑投影帧：算每帧平均亮度，>150 的基本都是 PPT/投影页，板书页另算（比逐帧看快得多）。

降级话术（正文顶部必须照写）：`> 本篇依据：仅目录与讲义，未核对原片。`

## 二·五 动手前先判定两件事：呈现方式、学科

这两个字段不判定，后面每步都会用错参数。判据写进 `_course.json`，结论写进讲义 frontmatter。

| 字段 | 取值 | 怎么判（看 3 帧：最早、中间、最晚） |
| --- | --- | --- |
| `presentation` | `ppt` / `blackboard` / `mixed` / `handout` | 整页排版好的公式+红蓝批注+角落人像窗 ⇒ `ppt`；一行行长出来的推导、擦黑板 ⇒ `blackboard`；两者都有 ⇒ `mixed`；只有文档没有原片 ⇒ `handout` |
| `discipline` | `math` / `ee` / `physics` / `cs` / `humanities` | 知识点是"条件与推导"还是"器件与引脚"，一眼能分 |

### 呈现方式决定四件事（判错方向会直接写错内容）

| | `ppt`（投影型） | `blackboard`（板书型） |
| --- | --- | --- |
| 谁为准 | **投影为准，口播只补"为什么"**（口播常念白字，转写错字多） | **板书为准，口播会串词**（老师可能讲错又自改） |
| 挑关键帧 | 翻页瞬间 + 批注写完那一刻 | 推导写完那一刻，**不许取半截推导** |
| 讲义骨架 | 结论式 → 条件 → 证明链 → 例题 | 机制 → 流程 → 时序/参数 → 故障现象 |
| 图的作用 | 让读者对上符号位置（"看①那个圈"） | 让读者看清推导怎么长出来 |
| 读图策略 | 一页一结论，挑 6–8 张、**会话模型 `read_image` 逐张读**即可 | 推导跨几十帧，**先让视觉模型批量扫帧选帧**，再回原片核 |
| 必做一步 | **老师跳过的部分必须显式标"老师没讲"**（ppt 型一集塞十几个知识点，必跳） | 板书与口播冲突时以板书为准，并在复查表记一条 |

`mixed` 按 `blackboard` 处理（板书可核验）；`handout` 一律加降级声明，不许写成"看过原片"。

**`mixed` 最常见的形态：题面是投影、推导全靠手写**（2026-11-21 ep25 实测）。
判定：投影上只有题目/定理陈述，红笔（或白板笔）在页面上现场写证明与算例 ⇒ 记 `mixed`，并且：

- **以手写推导为准**：口播会跳步，投影只给结论；
- 挑帧取"推导写完那一刻"，不许取半截；
- 录屏分辨率低（720P）时，**关键算式必须裁切放大再核对**（本篇例 4 的三处因式分解就是这样才发现原片笔误）。

### 学科只决定三件事（不另建模板）

1. 拓展点清单（写进"老师没讲到的"）；
2. 自测题型；
3. 复查红线集（见 `references/复查清单.md` §三）。

**明确不做**：不做"学科 × 呈现方式"的二维模板矩阵。理由：每套模板都要配独立复查标准，维护成本随格数爆炸；没有实测样本的模板只能靠想象。新增学科要有人实测过再用。

## 三、七段流程

每段都有产物和判据，判据不可观测就算没做完。

### ① 定位
解析链接（合集用集表映射，非合集按分 P）。产物：`<课程>/_course.json`（课名、合集、集表、术语词表、板块结构、`presentation`、`discipline`）。
判据：集号 ↔ 标题 ↔ 时长 ↔ BV/URL 四者能对上；两个形态字段有判定依据（哪一帧看出来的）。

### ② 取原片素材（课堂截图）
优先原片，因为它是本课语境。**默认「音频优先、视频按需」**（2026-11-21 定，`tools/course_prep.py`）：

1. 先 `course_prep.py audio <BV> <ep>` —— 只下 20~25 MB 音频，立刻转写出稿；
2. 有了转写、定了知识点，再用 `course_prep.py video <BV> <ep>` 下视频；只要几个时间点截图时加 `--keep 300-360,900-930`，**只保留需要的片段**，不留整集；
3. `course_prep.py frames <目录> --at 300,600,900` 按知识点时间点抽帧（`--every 10` 才是等间隔素材池）；
4. `course_prep.py verify <目录>` 出 `frames.csv`。

四种挑帧法：
1. **排序表优先**（2026-11-22 起首选）：`course_run.py rank <媒体目录> --near 1530,25:30,1740`
   —— 它把每一帧按「投影页 / 板书 / 空板 / 非板面 / 人物镜头」分类，给出板面占比、亮度、遮挡、
   字量、推荐分，并**按知识点时间点在窗口内挑最好的 1–2 张**；表在 `frames_rank.csv`。
   看表挑，不许盲读图（ep10 盲读 18 张只用上 10 张，白烧约 1 万 token）。
   **用之前先跑 ②-A 的失效判据。**
2. **视觉子代理批量筛选**（`rank` 判据不成立时用，见 ②-B）；
3. **关键词定位**：在字幕里找"如图／这个电路／看这里／我画一下／注意这个"，取该时间点 ±3 秒抽 2–3 张挑一张；
4. **知识点时间戳／兜底**：按"讲这张图的时间点"抽，或整集缩略图墙扫一遍。

### ②-A `rank` 表失效判据（**已废弃**，2026-11-23 ep16 起）

> **本节判据已失效**：`rank` 的 `kind` 列自 2026-11-23 起全部标 `REF*`
> （`REF候选/REF投影页/REF空板/REF人物`），不再输出「板书/非板面」分类。
> 因此下面统计 `kind` 占比的判据**永远触发失效**，不要再用。
> **直接走 ②-B 视觉子代理批量筛选。** 本节保留仅为历史回测参考。

```bash
# 以下命令已废弃，仅存档
python -c "import csv,collections;rows=list(csv.DictReader(open('<媒体目录>/frames_rank.csv',encoding='utf-8-sig')));c=collections.Counter(r['kind'] for r in rows);n=len(rows);print(c,'非板面%.0f%% 板书%.0f%%'%(100*c['非板面']/n,100*c['板书']/n))"
```

**原判据（已失效，勿用）：**

1. **「非板面」占比 > 80%**；或
2. **「板书」占比 < 5%**（`blackboard`/`mixed` 型课程必查这条）。

两条都要，因为单看第 1 条会漏：ep13 非板面 78% 卡在阈值下，但**板书 0 帧**——实际 20:00–32:00 全在写全微分。

回测（2026-11-23，同一门课 5 集）：

| 集 | 非板面 | 板书 | 判定 | 实际情况 |
| --- | --- | --- | --- | --- |
| ep10 | 5% | 73% | 可用 | 真可用，跟着表挑没出错 |
| ep11 | 1% | 60% | 可用 | 真可用 |
| ep12 | 1% | 83% | 可用 | 真可用 |
| ep13 | 78% | **0%** | **失效**（第 2 条） | 实为整段黑板 |
| ep14 | 87% | 1% | **失效**（第 1、2 条） | 实为整段黑板 |

- 失效的物理原因：整块深绿黑板被当成"非板面"。
- 失效时别删表：`green`/`light`/`edge` 三列仍可用——**按分钟采样看 `edge` 骤升的段**，那一带就是板书。
- 没失效也别全信：`kind` 只用来缩小范围，最终仍要读图。

#### ②-A-补：`rank` 的 `kind` 已彻底降级（2026-11-23 ep16 实测，**别再用它分类**）

上面那套「失效判据」只是**检测**，根因一直没修。ep16 补做了根因分析，结论是**修不了**：

用 ep14/15/16 三集真值（`frames_scan.csv`）算 `green` 对「有板/无板」的可分性
（Fisher 比值 = 类间方差 / 类内方差）：

| 集 | 有板组 mean(green) | 无板组 mean(green) | Fisher | 说明 |
| --- | --- | --- | --- | --- |
| ep14 | 12.4 | 1.1 | **0.35** | 不可分 |
| ep15 | **5.1** | **10.7** | **0.19** | **方向反了**：人物组比板书组还高 |
| ep16 | 10.3 | 1.3 | **0.43** | 不可分 |

Fisher < 1 意味着两类糊在一起，**任何阈值都不行**。事实也如此：固定阈值 7
在 ep16 上召回只有 **0.36**（漏掉 138 帧真板书）；换集内 p25 分位能到 0.96，
但 p25 是「固定 75% 通过率」的假设，而 ep15 真值只有约 40%——换个集就错。
换 Otsu 自动阈值也不行（ep16 算出 11.5，只放行 4%，真值 77%）。

根因：`green` 率随该集白平衡/曝光漂移（集间均值 **5.5% → 48.1%，差 7 倍**），
且黑板被老师挡住时 green 照样低、投影页白底时 green 也低。

**所以 `rank` 现在只出观测量，不下分类结论**：`kind` 全部标 `REF*`
（`REF候选/REF投影页/REF空板/REF人物`），输出末尾直接指路 `scan`。
连 `edge` 排序也不能用来挑帧——实测按 score 排前 4 名全是人物/开场帧，
因为人脸轮廓和字幕框的边比粉笔字还多。

**正确用法**：`rank` 只当「观测量速查」（看某段时间的 light/skin/edge），
挑帧一律走 `scan` 的段落表；确实要按知识点定位时用 `rank --near 10:20,22:00`
（它只在窗口内按 edge 挑，配合 scan 用不会跑偏）。
回归判据（不用测试脚本也能验）：拿一集判过帧的集重跑 `course_run.py kind`，
`kind` 列不该新增 `REF*` 标签，也不该冒出「这段是…」式结论句——
只允许观测量 + 板/投影/存疑 + 一句该怎么裁。

### ②-B 视觉子代理批量筛选（模型按你手上有的挑，本 skill 不指定）

图是**每步重放**的开销大头（一张 1.2k token，进来之后每一步都要重发）。所以"筛选"必须外包，
主模型只看一张文字表。**但文字也外包就废了**，见下面的能力边界。

**一条命令两段（2026-11-23 起固化，别再造轮子）：**

```bash
# 1) 出待判清单 + 提示词（--json 给 workflow 直接吃）
python tools/course_scan.py list <媒体目录> [--batch 6] [--json]

# 2) 子代理跑完，结果存 JSON（三种形态都吃），并表 → 段落表
python tools/course_scan.py merge <媒体目录> <结果.json>
#   → frames_scan.csv（t, frame, kind, kind_raw, occluded, text, status）
#   → 屏幕打印「段落表」：段号 / 起止时间 / 帧数 / 类型
```

脚本只做**纯本地的出清单与并表**，不自己打 API——沙箱内直连 dashscope 实测返回
`<400> InternalError.Algo: Temporary multimodal download failure: TimeoutError`
（base64 data-URI、JPEG 压缩、两个域名门牌都试过，全是同一句）。读图仍由会话里的 `workflow` 跑。

脚本里已固化三条判据，别在外面重写：

1. **失败帧 → `待人工`，不参与平滑**。脚本会单独列出"必须主模型亲自看"的帧号 + 时间；
2. **平滑窗口不足 3 个有效值就不动**。2 个值里"多数票"等于"另一个"，会把孤立但正确的判读改错
   （回测时 `f_0010` 就被这么误改过一次，所以加了这条）；
3. **JSON 容错**：` ```json ` 围栏、末尾多一个引号、夹说明文字，都能靠正则抠出
   `kind`/`occluded`/`text`；抠不出 `kind` 就算失败，不猜。

**分工（不许含糊）：**

| 环节 | 谁做 | 产出 |
| --- | --- | --- |
| 全部帧 → 候选帧清单 | 视觉子代理（**用你已配好的视觉模型**，见下方选型建议） | **只要 `kind` / `occluded` / 段落边界，`text` 一律丢弃** |
| 候选帧 → 按「歧义点数+1」筛选 | 主模型（用 `brief` 三档建议：弃用/必读/按需） | 最终要读的帧列表 |
| 选定帧的逐字抄写与核对 | 主模型自己读 | 讲义里的算式、错字判断、原片笔误 |

#### 选哪种视觉模型（这是实测结论，但**具体型号由你定**）

本 skill **不绑定任何 provider**：它只要求这个模型满足三条硬指标，你自己按已配好的模型挑。

2026-11-23 同批 20–33 帧、同提示词、对照人工目视真值做过三方对比，结论按重要性排：

| 指标 | 为什么是硬指标 | 当时观察到的差异（同批实测） |
| --- | --- | --- |
| **不编造** | 撞第一原则：读者没有纠错能力，编一个"像真的"公式最致命 | 有模型在被老师挡住半个板的 `f_0420` 上抄出一条板书上根本没有的式子；另一种模型写 `[模糊]` 自觉标注 |
| **null / 失败率低** | 失败集中在字最密的板书页＝最关键页 | 有模型 21%（7/33）直接返回 null，且全落在公式页 |
| **肯标 `[模糊]`** | 判据同上：宁可说不知道 | 只有一部分模型会主动标模糊位置 |

> 价格不该是第一条判据：这类批量筛选每集只烧几千 token，省下的钱远小于
> "混进一条编造公式"造成的返工。

**选型建议（按你手上有的挑，不必照抄）**

- 已有**视觉多模态模型**（能读 `read_image` 的）：直接用它，先用 5 帧试跑；
- 只有纯文本模型：**跳过 ②-B**，退化成"人肉看缩略图墙 + 主模型只读 10 张"（T2 路径，慢但不假）；
- 判断能不能用的**唯一办法**：拿你手上某一集、挑 3 帧已知内容（一帧板书、一帧投影、一帧被人挡住的）
  跑一遍，看它会不会把挡住的部分编出来。会编就换模型或降级。

**模型 id 的写法**随 provider 不同（有的要 `provider/model` 前缀，有的不要），
以你这台机器 `--model` 能看到的名称为准；**范例里的 id 只是曾用过的样本，不要当成规范**。

**角色分工（这条与模型无关，必须守住）：**

- 子代理：只出 `kind` / `occluded` / `bbox`（**筛选**）；
- 主模型：逐字抄写与核对那 10 张（**内容**）；
- 子代理给的 `text` **一律不进正文**——它挑的常是"最容易认的那行"，不是关键算式。

#### 这类视觉子代理的通病（所以 `text` 照样不许进正文）

- **偷懒**：20 帧里 12 帧抄的都是"已知：Rb、Rc、Vcc、RL"那一行——它挑**最容易认的那行**抄，
  不是每帧真正的关键算式；
- **`occluded` 判得粗**：`f_0660` 主模型判"无"它判"轻"，`f_2000` 主模型判"重"它判"轻"；
- **JSON 偶尔破格**：`f_1050` 的 `bbox` 多一个引号。解析要容错（见调用要点 6）。

⇒ **`kind`/`occluded`/`bbox` 用它的，`text` 不进正文。** 就算它不编，也不够细。

**调用要点（都踩过）：**

1. **每批 ≤ 6 个**并发——`workflow` 的 `agent` 活跃子代理上限 8，超了报 `subagent limit reached`，整批白跑；
2. **不要用 `opts.schema`**——套 JSON Schema 会让视觉模型**一个都不返回**（ep14 首轮 33/33 全 null）；
   改成提示词给格式、让模型手写 JSON、主模型解析；
3. **模型 id 按你这台机器实际注册的名称写**——带不带 `provider/` 前缀取决于 provider 怎么写，
   写错的表现是静默回落到默认模型（子代理不报错，结果全来自另一个模型）。
   验证办法：让它回一句"你是谁"，或看调用后的用量归属；
4. **它输出上限只有 65536**（官方是 393216）——所以批量任务**只能让它回三列**，
   绝不许让它一次吐长文本，否则撞长度上限；
5. **「没有 `kind` 字段」就算失败**，不是只看 null——实测有 1/279 帧返回的是一段
   "本会话没有 read_image 工具"的长解释而不是 JSON。重试 2 次，仍失败标「需主模型看」；
6. **JSON 解析要容错**：先 `json.loads`，失败就正则抠 `"kind"`/`"occluded"`/`"bbox"` 三个字段，
   别因为一个多余引号丢掉整帧结果；
7. 提示词明写"看不清写 `[模糊]`，绝不许根据课程内容猜测或补全"——实测有的模型会自觉写 `[模糊]`，
   有的照样编；**这条必须先试跑验证，别默认它有效**；
8. **`kind` 必须做 3 帧平滑**：单帧翻转是画面过渡抖动，取前后各 1 帧的多数票。
   ep14 实测 279 帧里 2 处抖动（`f_0670` 夹在两张投影间被判废帧、`f_2620` 同理），抹平即可。

#### 词表不许砍（2026-11-23 ep15 定，最反直觉的一条）

**「让模型少选几项会更稳」是错的。** ep15 我把 `rank` 原有的 5 类砍成 3 类
（板书/投影/废帧），结果模型被逼着做没有正确答案的选择：

| 帧 | 3 类词表说的 | 真相 | 后果 |
| --- | --- | --- | --- |
| `f_2590`/`f_2600` | 废帧 | 老师正面讲课镜头 | 无害，反正跳过 |
| `f_2650`/`f_2670` | 投影 | 教室全景，投影幕只占上方一条 | **有害** |
| `f_2700` | 板书 | 同上，黑板占一半但字很小 | 需裁剪 |

`f_2650`–`f_2700` 是 **44:10 到片尾**——全片最后 5 分钟。当成"投影"我就会去找不存在的投影帧，
或者直接跳过这 5 分钟。**而真内容恰在这 5 分钟的黑板上**（共集电路的 `Ro'=rbe/(1+β)`、
`Ro=rbe/(1+β)∥Re`、`Av≲1→1`、`Ri'=rbe+(1+β)Re`，前面没单独讲过）。

**正确词表 5 类，一个都不许少：**

```
板书 = 黑板/白板占画面主体，字能直接读清
投影 = 屏幕/投影幕占画面主体，字能直接读清
远景 = 教室全景，黑板或投影幕在画面里但只占一小块，字偏小需裁剪放大
人物 = 镜头对着老师或学生，画面里没有可读板面
废帧 = 黑场、台标、转场、纯墙壁
```

提示词里必须补这一句（补了之后 8 帧已知真值判对 7/8）：

> 注意：远景 和 人物 都**不是**废帧。远景说明那一时段有内容，只是要裁剪；
> 把它填成废帧会让后面的挑帧漏掉整段。

**平滑也不许跨类投票。** 跨类翻转往往是**真的镜头切换**，抹平它等于抹掉整段——
ep15 收尾 5 帧远景夹在板书中间，无保护时会被整段抹成「板书」，那 44:10 之后就没有可取帧了。
`course_scan.py` 已按组分隔：

```
板书 / 投影 → 直读组   远景 → 裁剪组   人物 / 废帧 → 空组
```

**远景帧用 `shots ... auto` 自动框黑板**（2026-11-23 ep15 新增）：

```bash
course_run.py shots <集目录> 2680:auto:0:共集输出电阻
#  → [16:37] t=2680 自动框黑板 (239,207,1099,441)
#  → ep15-t2680-共集输出电阻.png  2399x652
```

`auto` = 用严格绿判据（`g>r+4 且 g>b+4 且 g<150`）求包围盒，`scale=0` = 放大到长边 2400 px。
**质量闸用"宽而扁的横带"**：实测真板面 823×205 ≈ 4.0:1、高占比 0.28–0.32、宽占比 0.64–0.65；
而人物镜头 ≈1.1:1、学生席 ≈2:1、投影页 ≈1.9:1，全被判失败并**回退整帧**。
判据是 `长宽比 < 3.0 或 高 < 0.15H 或 宽 < 0.4W → 拒`。
（先试过"面积 ≥ 25%"和"高 ≥ 1/5"，前者把真远景也拒了、后者漏过人物镜头，都不行。）

实测 5/5：`f_2670`/`f_2680` 框对且字可读；`f_2590`/`f_2600`/`f_1880` 正确回退整帧。

#### 279 帧全量基线（2026-11-23，`vision_baseline.md`）

**这条最重要，必须单独看**：`text` 不是"偶尔不准"，是**会锁死在画面里最容易读的那个角落**。

ep14 的 `f_0710` 到 `f_2090` 共 **139 帧（23 分钟，全集推导主体）**，它抄回来的几乎全是同一句
——黑板右上角那块**永不变化的"已知/求"清单**：

```
已知：RB、RC、VCC、RL
求：Aus=Uo/Ui、Ri、Ro
```

而那 23 分钟里老师在写直流通路方程、交流通路、h 参数等效、`Au`、`Ri`、`Aus`、`Ro`、例题。
它**一次都没抄到**，只有约 15 帧偶然命中真公式。

⇒ 这产出的是"**看起来每帧都有信息、实际全是同一句**"的假稠密表。
**比 null 更危险**：null 你会去重读，假稠密不会。
**`text` 一律丢弃不是保守，是必须。**

它给的真正价值在**段落边界**，不在帧内容：

| 段 | 类型 | 用途 |
| --- | --- | --- |
| 连续 `板书` 帧段 | 板书区 | 直接告诉你"这几分钟都在写"，窗口内再挑时刻 |
| 连续 `投影` 帧段 | 投影区 | 同上；同一页会连续几十帧，取中间那张最稳 |
| `废帧` | 空板/人物 | 排除 |

**机器给的是"段落"，不是"帧"。** 段内取哪一刻仍由主模型按内容定——这一步没有省掉。

#### 读图预算 = **判断点数 + 1**，不是固定 10 张（2026-11-24 ep17 复盘后改）

**旧规矩作废**：以前写"主模型自己读的张数 ≤ 10 张"，这是个拍脑袋的常数。
ep17 实测：我一集读了 **17 张**，回头数，其中**只有 3 张是"不读就会写错"的**
（`t1650` 三个接法面板哪个极接地、`t1470` 共集/共基那句谁错、`t1380` 作对照）。
另外 14 张里 6 张是重复板面、4 张是老师挡板——**这 10 张根本没产生任何信息**。

**新判据（写死）**：

> 主模型自己读的张数 = **会让讲义写错的歧义点数 + 1**（兜底一张）。

不是"每集 10 张"、也不是"每个知识点 1 张"。**要先数歧义点，再决定读几张。**
ep16 的歧义点只有 1 个（`Ro=RC` 靠 KVL 证明 `ib=0`），ep17 有 2 个，所以两集的
合理张数是 2 和 3——**不是 10 和 17**。

**歧义点的定义**（满足任意一条才算）：

- 一句话里**器件名和理由打架**（ep17 的"共集/共机"）；
- 几个子图**不放大就分不清归属**（ep17 的 (a)(b)(c)）；
- 一个数值/公式**读出来有两种可能**（ep16 的通频带倍数 L1863 vs L1871）。

其余"看清细节""确认和我记的一样""再核一遍"，**一律不算歧义点**，不许为它读图。

##### 结构可以外包，文字不能外包

分界线是固定的，别自己改：

| 可以交给子代理（`brief`） | 绝不能外包，必须主模型亲眼看 |
| --- | --- |
| 这帧有没有**成页的图 / 整幅曲线 / 完整电路图** | 公式原文 |
| 板面上有几块要素、要素各是什么 | 手写符号的下标（`β1` 还是 `β2`） |
| 可读性（清晰 / 被挡 / 模糊 / 字太小） | 箭头朝哪（判 `NPN`/`PNP` 的命门） |
| 它自己对这个判断的置信度 | 数值 |

**为什么文字不能外包**：ep14 的 279 帧全量基线已经证明，子代理读手写板面时会
**锁死在画面里最容易读的那个角落**——139 帧抄回来全是黑板右上角那句不变的
"已知/求"，而那 23 分钟真正在写的直流通路、h 参数、`Au`、`Ri`、`Ro` 一条没抄到。
产出的是"**看起来每帧都有信息、实际全是同一句**"的假稠密表，**比 null 更危险**
（null 你会去重读，假稠密不会）。

**用法（两段，和 `scan` 一样）**：

```bash
# ① 出提示词 + 候选帧清单（只对候选帧跑，不是全片）
course_run.py brief <媒体目录> --times 450,540,1650 --json

# ② 子代理跑完存 JSON，并表 → 三档建议
course_run.py brief <媒体目录> --times 450,540,1650 --result 结果.json
#   → 时刻 | 帧 | scan类别 | 子代理判 | 成页图 | 要素 | 可读 | 置信 | 建议
```

**三档建议的规则**（`cmd_brief` 里写死，回归项 T6）：

| 建议 | 条件 | 你该做什么 |
| --- | --- | --- |
| **弃用** | `被挡` 或 `模糊` | **换个时刻重挑，这张不读** —— 这是最省的一笔 |
| **必读** | `字太小` / 置信「低」/ 成页图「有」 | 字太小配 `look` 裁切放大；后两种要抄公式、或子代理拿不准 |
| 按需 | 其余（干净的板书页） | 由"歧义点数"决定读不读 |

> **踩过的坑**：第一版把「字太小」判成"弃用"，而它恰恰是**该放大后再读**的那一类
> （ep17 的 `t1650` 就是），已纠正并写进 T6。分档规则改一个字都会影响挑帧，**必须进回归集**。

空板、观众席、人物特写一律不读；不要读 4000 px 高的长条裁切，改读 2–3 张 300 px 宽的小裁切。


### ②-C 先量标尺再裁图（2026-11-23 ep14 定 · **2026-11-24 ep23 升级为闸门**）

**禁止"猜坐标 → 裁 → 读"。** ep14 为此白读 6 张（裁到老师身上、黑板上沿空白），每张还要重拍一次。

正确顺序，**只多花一步**：

1. 读 **1 张整帧**（通常最早那张，画面稳定）；
2. **从这一张量出板面矩形**：左板／右板／投影区的 `x1,y1,x2,y2`，记进 `00-知识点.md` 的挑帧记录；
3. `course_run.py shots` 一次批量裁（`t:crop:x1,y1,x2,y2:scale:名字`）；
4. 每张裁切图**只读一次**，读完定稿。

#### 闸门（ep23 实测后从"判据"升为"开工前必过的一项"）

ep23 我把这条当成"建议"，结果重裁 6 次、读了 26 张图，单项烧掉约 2M prompt token。
所以在这里立闸门，**用可观测的事实判定，不靠自觉**：

| 闸门 | 判据（机器可查） | 不通过时怎么办 |
| --- | --- | --- |
| **G1 标尺已量** | `00-知识点.md` 里有一条"板面矩形"记录（含 `x1,y1,x2,y2` 与它取自哪张帧） | 没记录就不许跑 `shots` |
| **G2 无二次裁切** | 对同一时间点 **±10s** 内（`--tight 10`）、或同一块板面区域，`shots` 只调用过一次 | 出现第二次 = 没量标尺，**停下重新量**，不许再猜 |
| **G3 读图数 ≤ 歧义点+1** | 本节 ②-B 的"歧义点数 + 1" | 超了说明在读"看清细节"，一律不算歧义点 |
| **G4 裁完先看缩略图再读全图** | 每张裁切图先用 `PIL` 缩到 1/3 出 JPEG 预览（约 30 KB）确认框对了，再 `read_image` 读原裁切 | 直接读原裁切＝赌框对了，赌错就要重裁＋重读两道成本 |
| **G5 ≥15 点必须拆篇** | `course_gate.py parts <集> --strict`，退出码 0 | 新集交付**必须带 `--strict`**；历史集默认只 WARN，不追溯 |

**G1 的具体做法**（一条命令，别手搓）：

```bash
# 读一张整帧，量出板面矩形
python tools/course_run.py look <媒体目录> "<最早时刻>" --full --no-scan --max 1100
```

看图后把矩形填进 `00-知识点.md` 的一个固定小节（`course_gate.py ruler` 认这个格式）：

```markdown
## 挑帧记录
- 板面矩形（取自 f_0220 投影区）：x1,y1,x2,y2 = 70,50,1120,550
- 板书区（取自 f_1860）：x1,y1,x2,y2 = 0,0,1280,430

**歧义点：2**
1. ……（一句话说清为什么这个点不读图就会写错）
2. ……
```

之后**所有** `shots` 调用都套用这些矩形，不许再凭图猜坐标。

**闸门一条命令收口**（`report` 是打包版，四个子命令也能单独跑）：

```bash
python tools/course_gate.py times  <媒体目录> "220,900,2980,3450"
python tools/course_gate.py ruler  <集目录>
python tools/course_gate.py rects  <集目录>   # G2，读 shots.log
python tools/course_gate.py report <集目录> --read-images 6 [--strict]
# 退出码 0 = 全过；1 = 有闸门未过（会打印是哪一条、怎么修）
# --strict 只影响 G5（拆篇）：不带它时 ≥15 点单篇只报 WARN，带了才 FAIL
# --read-images N 填【实际读了几张】，不是预算上限；G3 拿它和「歧义点数+1」比
```

**G2 的数据从哪来**：`course_run.py shots` 从 2026-11-24 起，每次裁图都往
`<媒体目录>/shots.log` 追加一行（`t / box / name / file / stamp`）。
`rects` 读这个文件，判据是**时间邻近**（默认 `--tight 10` 秒）——不是比 box 是否相同，
因为重裁时坐标一定被改过，比 box 一个都抓不到（这一点我第一次就写错了）。

`--tight 10` 是用 ep23 真值校准的：10 秒抓出 2 对真重裁、0 误报；30 秒会多出 2 对
不同板面的误报。**宁漏不误报**——误报会让人习惯性忽略这条闸门。

**闸门自己也要有回归**（改了 `course_gate.py`，用真集反测这四条，发布包不带夹具脚本）：

```bash
# 1) G2 真抓得到：挑一集已知重裁过的，必须报出来
python tools/course_gate.py rects <集目录> --tight 10
# 2) G3 不许被绕过：不给 read_images 必须 rc≠0（第一版就是这里 return 0）
python tools/course_gate.py budget <集目录>
# 3) times 容错：负值与越界时刻要被剔除，不能被 argparse 当选项吃掉
python tools/course_gate.py times <媒体目录> "-5,100,99999"
# 4) G5 两种档位都要对：不带 --strict 只 WARN，带 --strict 必须 FAIL
python tools/course_gate.py parts <集目录> --strict
```

**判据**：四条里任何一条「该报没报」或「该 FAIL 却 rc=0」，闸门就是空壳，别信它的 OK。

> 为什么闸门要配回归：第一版 `course_gate.py` 我写完就报"改好了"，实际上
> **G2 只在文档里存在、代码里没实现**，G3 缺参数时还 `return 0`（闸门能被绕过），
> `times "-5,100"` 直接被 argparse 当选项吃掉。三条都是跑测试才暴露的。
> **闸门类代码的判据必须用真值反测一遍**，否则它只是个看起来对的空壳。

> **为什么 G4 值得**：缩略图确认框 ≈ 30 KB（约 20 token），重裁一次 + 重读一次 ≈ 1.5k token。
> 25 倍的差价，没有理由跳过。

**省 token 四条硬规矩**（2026-11-22 ep10／2026-11-23 ep14 实测后定）：
- **不许 `cat meta.json`**：单行 30 KB、几乎全是带签名的 playurl 直链，标题时长 MANIFEST 已打印；
- **长任务前台跑**（`ops_bash` + 大 timeout，fetch 全程 7 分钟），别用 `Start-Process` 起后台——
  子进程会跟着后台作业一起被带走，日志 0 字节，白跑一轮；
- **LLM 摘要那层别要**（`course_run.py digest` 只出机械稿）：它和子智能体的知识点卡重复，
  ep10 那 23 条一条没用上；且 `digest` 本身要看压缩率，< 80% 就跳过（见 ③）；
- **裁切目录写工作区内**：`/tmp` 不在工作区，`PIL.save('/tmp/x.png')` 直接 `POLICY_DENIED`，
  写 `<媒体目录>/tmp/` 再用；用完删掉。

#### 九条省 token 的命令（2026-11-23 ep16 复盘后加 · 2026-11-24 ep17 补 `brief`，**按顺序用**）

ep16 花了和 ep15 一样多的轮次，但内容更简单——钱全花在"补我自己工具链的洞"上。
下面五条把那些洞堵成命令，**别再手搓**：

| 阶段 | 命令 | 代替什么 |

**读原文交给子智能体（2026-11-22 起是默认做法，不再是"可选"）**

用 `workflow` 把"读 `transcript.txt` 全篇 → 出知识点卡"派给子智能体，
原文**不进主会话上下文**，主会话只收卡片。
2026-11-22 实测：`agent(..., {provider:"<你的provider>", model:"<你的模型>"})` 覆盖可用
（子智能体自报的模型名可用于确认覆盖真的生效），挑一个便宜/免费的读全文模型即可；
而主会话直读会让**后续每一步**都重放那几万 token。代价是卡片同样要回原文核对。

**卡片 schema 只收"事实"，不收"散文"**（ep10 实测后定）：

```
必需字段：id / title / time_start / time_end / seg_start / seg_end / key_quotes / numbers / caveats
不要字段：what / why（"这件事是什么/为什么"那两段散文由我写，让子智能体写等于让我再读一遍）
可选：figures_hint / outline / non_teaching / gaps
```

理由：`what`/`why` 约占卡片体量的一半，而它们写出来之后我照样得回原文核对一遍；
只收"段号 + 原话 + 数字"反而更省，且更适合直接当讲义骨架。
`numbers` 每项必须带 `seg` 和 `quote`，这是后面逐条核对的唯一抓手。

### ④ 素材检索与核验（网上原理图）

```

ep22 我这么改，一次吞掉 **5 个图块**，`note_check` 报"引用 1 处 / 5 张孤图"才发现，
只能整篇重写——净成本是**两次全篇输出**（约 4 万字符）。

**正确做法，按代价从低到高**：

| 优先级 | 手段 | 适用 |
| --- | --- | --- |
| 1 | **写之前先算配额**（`course_budget.py plan`） | 永远该先做，避免写完再砍 |
| 2 | **整篇重写**（一次写对） | 需要动的节 >3 个，或结构要变 |
| 3 | **按行号定位替换**（`lines[61] = ...`，先 assert 内容前缀） | 只改 1–2 行文字 |
| 4 | ~~标题切片替换~~ | **禁用** |

**修剪字数也有闸门**：ep23 为砍字数跑了 6 轮 `note_check`，每轮只砍掉 20–70 字。
规则：**先按行号一次砍够（目标 ≤ 上限 −100），再跑 `note_check` 验收**，
不许"报一次错砍一点"地来回磨——那是 ep08 烧 11.8M 的老毛病换了个形式。

### ⑥ 复查
另起一遍，按 `references/复查清单.md` 三层查（事实/逻辑/阅读），红线**按 `discipline` 取集**、逐条附证据位置。
产物：`90-复查/ep31-review.md`。通过才把 `status` 改成 `reviewed`。
**不通过不许交付。**

### ⑦ 台账、索引与下集开工提示词
扫 frontmatter 自动生成 `00-课程地图.md` / `00-索引.md` / `99-台账.md`。状态列一律自动生成，不许手写（手写必漂移）。

**每集收尾必须再出一份「下集开工提示词」**——它和台账是一件事的两半：台账让**人**看见进度，提示词让**下一个会话**能直接开工。写在哪按宿主形态二选一（不许两处都写，也不许都不写）：

| 宿主形态 | 写在哪 | 判据 |
| --- | --- | --- |
| 有集级交接卡的 | 新建**下一集**的卡 `05-EP(N+1)交接.md`；本集卡的 frontmatter 改 `status: 已完成` 并在顶部指向新卡 | 新卡的「开工第一句」能整段直接粘给新会话，粘完就能跑 |
| 只有专属热卡的 | 把下一集那句话写进热卡 | 热卡若是脚本生成的，**改生成脚本、不要手改**，否则下次生成就冲掉 |

提示词必须自带四样，缺一样新会话就得回头翻旧对话：

1. **参数**：BV、集号、讲义目录、素材目录，以及本集的呈现方式（未定就写"未定，看第 4 步 kind"）。
2. **内容接点**：上一集末尾老师明确留下的钩子——**原话 + srt 行号**，并写明"下集从这里接、不许在本集越界补写完什么"。
   判据：新会话读完这一条，不需要判断"该不该提前写下一节的内容"。
3. **本集新踩的坑**：只写**会重复犯**的那几条，每条给规避动作；不要把全量踩坑表抄进来（那是 `02-工具与踩坑.md` 的活）。
4. **开工第一句**：一句可直接复制的话，含"先跑自检确认全 PASS"和"第 4 步整集 `kind` 不能跳"。

⚠️ 提示词里只写**参数与接点**，不要写本集的结论总结——结论在讲义里，提示词写多了会诱导新会话跳过"自己读原文"这一步。

## 四、写作硬规则

| 规则 | 判定 |
| --- | --- |
| 每个卡点 ≥2 种讲法，≥1 种非文字 | 卡点＝出现新符号/寄存器位/公式/流程/时序 |
| 每个比喻后面写"到哪儿不成立" | 缺这句等于不合格 |
| 数字必须带单位并算给人看 | "72 MHz ÷ 7200 = 10 kHz"，不许只给结论 |
| 禁用词 | 显然／很简单／众所周知／大家应该都知道 |
| 单篇字数 ≤ **知识点数 × 400 + 800** | 容差带内算合格，别为卡整数反复删句；超带才动 |
| 单个知识点 ≤ 400（400–480 warn，>480 改） | 容差同总量，判据统一走 `tools/note_check.py` |
| 图片必须被正文讲解 | 只贴图不讲＝删 |
| 推测与事实分开 | 推测标 `未核对` |

细节见 `references/讲解工具箱.md`。

## 五、交付前验收（17 条，缺一条退回）

1. 关掉原片只读这篇，能答五问：解决什么问题／机制／步骤及每步为什么／一个常见错误及现象／2 道自测；
2. 每个卡点 ≥2 种讲法、≥1 种非文字；
3. 每个比喻有失效边界；
4. 无禁用词；
5. 单篇 ≤ 知识点数 × 400 **+ 800** 字，且单个知识点 ≤ 400 字（400–480 记 warn）——判据统一跑 `tools/note_check.py`；
6. `evidence` 与正文一致，低证据有降级声明；
7. 每篇 ≥1 个易错块、1 个反例；
8. 每张图有来源 + "这张图要你看什么"；
9. 网上图有核验记录（型号/引脚/参数）；
10. 无来源、无引用、未核验的图不出现；
11. 每张图有引导句、标号、逐点解读、对照表；
12. 复查表存在，红线（按 `discipline` 取集）逐条有证据位置；
13. `status: reviewed` 与复查通过状态一致（复查表里要有字面「结论：**通过**」，`note_check` 会查）；
14. **同一处的几个数必须互相印证**：口述与算式冲突时**按算式定**，并在正文里公开写明
    "原片口述方向说反了"——不许顺着矛盾写，也不许悄悄改掉老师的话
    （2026-11-24 ep18：「变比 1:2」vs「8 Ω×4=32 Ω」，只有 `N1:N2=2` 能同时满足后两个数）。
15. **pipeline 闸门全过**：`tools/course_gate.py report <集目录> --read-images N --strict` 退出码 0
    （G1 标尺已量 / **G2 无二次裁切** / G3 读图不超预算 / **G4 裁完先看缩略图** / **G5 ≥15 点必须拆篇** / 图块与 assets 双向对齐）。
    `--read-images N` 填**实际读了几张**，不是预算上限。G3 超预算不算"内容错"，
    但必须在复查表里写明超了几张、超的那几张各读到了什么——**读了却没进正文的，就是白读**
    （2026-11-24 ep23：读 6 张、预算 3 张，超的 3 张确实没产生新信息）。
16. **成本自查**：若本轮 `read_image` > 6 张、或 `shots` 重裁 > 1 次，复查表必须写下原因。
    ep23 的教训是这一类成本**不会自己暴露**——交付物看起来完全正常，钱是在上下文重放里烧的。
17. **下集开工提示词已落地**（见 ⑦）：按宿主形态二选一写了（下一集交接卡 / 专属热卡），四样齐全
    （参数 / 内容接点带 srt 行号 / 本集新坑带规避动作 / 开工第一句）；本集旧卡已标完成并指向新卡。
    判据：**把「开工第一句」原样粘给一个全新会话，它不需要问任何问题就能开工**——问一句就算没写够。


## 六、禁止事项

- 只看标题/目录就写笔记，不抽帧、不读字幕；
- 把网图静默当正确（不做核验、不写差异）；
- 用"课程太大/时间不够"跳过抓取；
- 把这份讲义说成"你学过的""你的笔记"（它是整理产物，不是学习记录）；
- 未复查就标 `reviewed` 或直接交给用户；
- 把第三方图片打包进 skill 分发（只给 URL + 复现命令）。

## 七、可移植配置

本 skill 不绑定任何机器路径。可选项：

- 环境变量 `COURSE_OUT`：产物根目录，默认 `./course-notes`；
- `_course.json` 里的 `terms`：转写术语词表（缺省用通用词）；
- `_course.json` 里的 `bin`：yt-dlp / ffmpeg 路径，缺省从 PATH 找。

脚本（可选，未安装时按 T0–T4 降级手工做）：`scripts/course.py`（grab / shot / at / outline / index / annotate / review-sheet）。

# 格式模板（只有格式，没有内容）

> 这份文件只回答一个问题：**写成什么样才不会被闸门打回**。
> 例题、电路、公式、真实知识点一律不在这里——那些由原片和知识点卡决定。
> **照抄结构，不要照抄任何例子。**本文件故意一个例子都不带：
> 带一个，下一个会话就会把它原样抄进讲义。
>
> 与 `references/单篇模板.md` 的分工：那份讲**怎么写**（带示例片段），
> 这份讲**长什么样**（字段、骨架、判据）。**结构以本文件为准。**

## 一、文件名

```
10-讲义.md                        单篇
10-讲义-上.md / -中.md / -下.md    拆篇（知识点 ≥15 必须拆）
```

拆篇只许这四个后缀。写成 `10-讲义-1.md`、`10-讲义1.md` 这类，索引与台账扫不到，
表现是「这一集不见了」——**不报错，直接静默丢集**。

## 二、frontmatter（10 个必填键）

```yaml
---
course: <课程标识，与集目录 _course.json 的 course 一致>        # 必填
episode: <集号，整数>                                          # 必填
topic: <本篇主题>                                              # 必填
presentation: <ppt | blackboard | mixed | handout>             # 必填（缺失只 warn）
discipline: <math | ee | physics | cs | humanities>            # 必填（缺失只 warn）
knowledge_points: [K1_<名字片段>, K2_<名字片段>, K3_<名字片段>]  # 必填，数个数算字数预算
evidence: <transcript | frames+transcript | slides | outline_only>  # 必填
figures: <classroom | web | redrawn，多种用逗号>                  # 必填
status: <draft | reviewed>                                     # 必填，只许这两个值
review: 90-复查/ep<NN>-review.md                                # 必填，相对集目录
updated: <YYYY-MM-DD>                                          # 必填
---
```

- 除 `presentation` / `discipline`（老集缺只 warn）外，**任何一项缺失都是 FAIL**；
- `status` 写别的值直接 FAIL；
- `status: reviewed` 时，`review` 指向的那份复查表里必须有字面 `结论：通过`；没有 ⇒ FAIL；
- `knowledge_points` 用 `K<数字>_` 计数：**数出几个，字数预算基数就是几个 × 400**；
- 拆篇后每篇各写自己那份，`knowledge_points` 只列本篇的；**合并时取并集**，
  否则预算会掉一半——而错误方向是「看起来更宽松」，比报错危险。

## 三、章节骨架（顺序固定）

```markdown
# ep<NN> · <主题>

> **30 秒速览**
> - 解决什么问题：<一句话>
> - 一句话机制：<一句话>
> - 最容易错：<一句话>

> 本篇依据：<evidence 说明；低证据必须写降级声明>

## 0. 这一集在整门课的位置
## 1. 前置补丁
## 2. 知识点
### K1 · <名字>
### K2 · <名字>
## 3. 动手（最小可跑）
## 4. 自测
## 5. 老师没讲到的
```

知识点标题的唯一硬要求：**`K<数字>` 必须出现在标题正文开头**
（前面允许有 `1.` / `2、` 这类序号，之后不许再有别的字）。

**反例（会被切错）**：`## 3. 一条时间线（把 K2 与 K4 串起来）` ——
`K3` 出现在标题正文开头，会被当成「K3 那一节」，凭空多切一节，知识点数虚高、字数配额一起错。
要把几个 K 串成一段，标题里不许出现 `K<数字>`。

单篇（≤14 点）偏长时：第 0 节把全篇分成 2–3 个块并说明每块回答什么；
知识点编号连续、不跳号。

## 四、图块（四行固定结构，差一行就报错）

```markdown
![图<N>](assets/ep<NN>-t<四位秒数>-<名字>.png)

> 图 <N> · 来源：<原片时刻或出处> · 要你看：<一句话>

逐点解读：<①②③ 逐点讲，≤140 字>
```

四条判据，每条都有代码在查：

| 判据 | 违反后果 |
| --- | --- |
| `> 图 N` 后面必须紧跟分隔符，只认 **`·`（U+00B7）** 或 **`.`（ASCII 句点）** | 认不出图注：图号连续性和「有没有讲解」同时失效 |
| 图注编号 `1..N` 连续、不重复 | **FAIL** |
| `逐点解读：` **必须在行首**（写进 `>` 里就算没讲） | 图后解读恒为 0，看起来像没超标，实则正文虚高 |
| 图下方讲解块 ≥30 汉字 | **FAIL**（只贴图不算讲） |

**分隔符这条要按代码写，不按习惯写**：代码里的字符类是 `[··.]`，
两个 `·` 都是 **U+00B7**，第三个是 ASCII `.`。
常见的中文间隔号 `・`（U+30FB）、项目符号 `•`（U+2022）、`|`、`：` 全部**认不出**。

另外两条**没有代码兜底**，只能靠这里写死：

1. `![图N]` 的 alt 编号与 `> 图 N` 的图注编号是**两处独立编号**，插图/删图后两处一起改；
2. 图注里的时间与文件名里的 `t<四位>` 要能对上（闸门按 ±2 秒试「秒数」和「MMSS」两种口径，
   都对不上只 warn）。**新集一律用秒数**，不要混用两种口径。

## 五、字数与禁用词

| 项 | 阈值 | 级别 |
| --- | --- | --- |
| 全篇正文 | ≤ `知识点数 × 400 + 800` | 超 = FAIL |
| 单个知识点正文 | ≤ 400 正常；400–480 warn；> 480 | FAIL |
| 图后逐点解读 | ≤ 140 | warn |
| 禁用词：`显然` / `很简单` / `众所周知` / `大家应该都知道` | 出现即 | **FAIL**（转述原话也不行） |

口径要点：

- **`>` 开头的行只有 `> 图 N` 那种图注豁免正文统计**，速览框、依据框、引用块**全部算正文**。
  这是「速览必须压到三行」的真正原因；
- 代码块、`$$` 公式块、表格、`<details>`、标题行、图注、`逐点解读` 行都不计入正文；
- 容差带内算合格，**不要为了卡整数反复删句**；只有超 `上限` 才动，
  动的话先删填充句，仍超再考虑拆篇（拆篇触发条件仍是 ≥15 知识点，不因超字数而拆）。

## 六、`00-知识点.md` 里闸门要的两样

| 内容 | 判据 | 谁在查 |
| --- | --- | --- |
| 一节 `## 挑帧记录` | 必须有这个子串；分篇时也写在 `00-知识点.md`，不要拆到各篇 | 标尺闸门 |
| 板面矩形 | `x1,y1,x2,y2 = <整数>,<整数>,<整数>,<整数>` | 标尺闸门 |
| `**歧义点：N**` | 读图预算 = N+1 | 读图预算闸门 |

最小形态（数字全部换成实测值）：

```markdown
## 挑帧记录
- 板面矩形（取自 f_<四位>）：x1,y1,x2,y2 = <N>,<N>,<N>,<N>

**歧义点：<N>**
1. <一句话说清：不读图就会写错在哪里>
```

**歧义点的合格定义**（满足任意一条才算，其余「看清细节」「再核一遍」都不算）：

- 一句话里器件名和理由打架；
- 几个子图不放大就分不清归属；
- 一个数值/公式读出来有两种可能。

先数歧义点，再决定读几张图——**不是固定 10 张，也不是每点 1 张**。

## 七、复查表

`90-复查/ep<NN>-review.md`，正文里必须有一行 `结论：通过`
（`结论` 后可用 `:` 或 `：`，允许 `**` 包裹）。
**`通过` 与 `不通过 / 未通过 / 打回 / 驳回` 并存 ⇒ FAIL**——收尾时先把旧结论清掉再写新结论。
